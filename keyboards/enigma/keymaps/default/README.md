# Macros

Keys A-E each run a macro and show a short name on the OLED when you hold
the info key (F) and press them. There are up to 4 macro layers — hold
A+B together (no need to also hold F) to cycle to the next one; the
current layer (`L1/4`, etc.) is always shown on-screen, top-left during
peek, top-of-screen when idle. To change what a key does on a given
layer, or its label:

1. Edit [macros.json](macros.json) — `layers` is a list (up to 4) of
   `{"keys": {...}}` objects. Each key A-E takes a `name` (shown on the
   OLED) and a list of `actions`; a key can be left out of a layer
   entirely if that layer has no use for it, it'll just do nothing there.
   An action starting with `TAP:` sends that QMK keycode
   (`"TAP:LCTL(KC_C)"`, `"TAP:KC_ENTER"`); anything else is typed out
   literally as text.
2. Regenerate the C source: `python3 generate_keymap.py`
3. Rebuild and flash: `qmk compile -kb enigma -km default && qmk flash -kb enigma -km default`

`keymap_macros.h` is generated by that script — don't hand-edit it, your
changes will be overwritten the next time it runs. F itself is fixed
(tap = `KC_F`, hold = show info) and isn't part of `macros.json`, since
it doubles as the layer key that makes peeking work at all.

The A+B layer-cycle combo means A and B specifically have a small
(default 50ms) delay before their own macro fires, while QMK waits to
see whether B follows A — not noticeable in practice, but it's why those
two keys feel marginally less instant than C/D/E.

Keep names short — the OLED is ~21 characters per line in the idle
view, and long names just get cut off / run into the next line rather
than wrapping cleanly. On the peek screen, names over 7 characters
render smaller (2x scale instead of 3x) to keep them from running off
the edge.
